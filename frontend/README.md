# HASAD Frontend — حصاد

واجهة عربية RTL مستقلة لمنصة حصاد، مبنية باستخدام React وVite وJavaScript.

## المتطلبات
- Node.js 18 أو أحدث
- تشغيل Backend الحالي على `http://localhost:27000`

## التشغيل
```bash
cd frontend
npm install
cp .env.example .env
npm run dev
```
يفتح Vite عادةً على `http://localhost:5173`. إعداد التطوير يمرر طلبات `/api` إلى `http://localhost:27000` عبر proxy. لا يتطلب ذلك تعديل إعدادات CORS في الخادم أثناء التطوير المحلي.

للبناء:
```bash
npm run build
npm run preview
```

يمكن تغيير `VITE_API_BASE_URL` في ملف `.env`. القيمة الافتراضية `/api` ملائمة مع Vite proxy.

## الصفحات
- عامة: الرئيسية، تصفح المحاصيل، طلبات التوريد، تسجيل الدخول، إنشاء الحساب.
- المزارع: لوحة التحكم، محاصيلي (تصفية قائمة المحاصيل العامة بحسب المالك)، إضافة محصول، تقديم عرض على طلب، الاتفاقيات.
- التاجر: لوحة التحكم، طلباتي (تصفية الطلبات المفتوحة بحسب مالك الطلب)، إنشاء طلب توريد، مراجعة عروض الطلب وقبولها أو رفضها، إنشاء اتفاقية من العرض، الاتفاقيات.
- المدير: لوحة التحكم، إضافة التصنيفات والمناطق.

## مسارات API المستخدمة فعلياً
| Method | Endpoint | الاستخدام |
|---|---|---|
| GET/POST | `/api/auth/register` | التسجيل |
| POST | `/api/auth/login` | تسجيل الدخول |
| GET | `/api/auth/me` | التحقق من الجلسة |
| GET/POST | `/api/crops` | عرض المحاصيل / إنشاء محصول |
| GET/POST | `/api/supply-requests` | عرض الطلبات / إنشاء طلب |
| POST | `/api/offers` | تقديم عرض |
| GET | `/api/offers/request/:id` | عروض طلب يملكه المستخدم |
| PATCH | `/api/offers/:id/accept` | قبول عرض |
| PATCH | `/api/offers/:id/reject` | رفض عرض |
| POST | `/api/agreements` | اتفاقية شراء مباشر |
| GET | `/api/agreements/my` | اتفاقيات المستخدم |
| POST | `/api/agreements/from-offer/:offerId` | إنشاء اتفاقية من عرض مقبول |
| PATCH | `/api/agreements/:id/confirm` | تأكيد الاتفاقية |
| PATCH | `/api/agreements/:id/cancel` | إلغاء الاتفاقية |
| PATCH | `/api/agreements/:id/complete` | إتمام الاتفاقية |
| GET/POST | `/api/categories` | عرض التصنيفات / إضافة (مدير) |
| GET/POST | `/api/regions` | عرض المناطق / إضافة (مدير) |

## حدود معروفة من الـ Backend الحالي
- لا يوجد endpoint لتعديل أو حذف المحاصيل؛ لذلك لا تعرض الواجهة هذه العمليات.
- لا يوجد endpoint لإغلاق أو تعديل أو إلغاء طلب التوريد؛ لا تنفذ الواجهة هذه الأفعال.
- لا يوجد endpoint لجلب عروض المزارع الخاصة به؛ يمكن للمزارع تقديم العروض، لكن لا توجد صفحة موثوقة لقائمة كل عروضه وحالاتها.
- لا يوجد endpoint لجلب المحاصيل أو الطلبات الخاصة بالمستخدم مباشرة. تعرض الواجهة قائمة السوق العامة ثم تصفي النتائج محلياً باستخدام بيانات المالك التي يعيدها الـ populate. لذلك قد لا تظهر سجلات غير مدرجة ضمن النتائج العامة.
- لا يوجد endpoint لتفاصيل اتفاقية منفردة؛ تعرض الواجهة قائمة الاتفاقيات وإجراءاتها المتاحة.
- لا يوجد دفع إلكتروني. حجز المخزون يتم على الخادم بعد تأكيد الطرفين.
- لا يمكن إجراء اختبار تكاملي فعلي دون تشغيل قاعدة البيانات وخادم الـ Backend وبيانات دخول صالحة.

## ملاحظات
- لا يتم تعديل أي ملف Backend.
- رمز JWT يحفظ محلياً ويرسل في `Authorization: Bearer`.
- عند استجابة 401 يتم إنهاء الجلسة محلياً. لا يوجد refresh-token endpoint.
- الصور من Unsplash والخط من Google Fonts؛ يلزم اتصال إنترنت لظهورها.
